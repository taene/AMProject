# AMProject 기술 문서 및 트러블슈팅 가이드

## 1. 문서화 아키텍처 및 설계 철학

본 프로젝트의 트러블슈팅 및 기술 문서는 **'도메인(분야) 별 분리'** 원칙하에 작성 및 관리된다.

이러한 문서화 구조를 채택한 핵심 이유는 다음과 같다.

* **도메인 자산화 구축:** 개발 과정에서 겪은 문제와 해결책을 분야별로 한눈에 파악할 수 있도록 모아, 단순한 에러 로그를 넘어 개발자 개인의 강력한 '도메인 지식 자산'으로 승화시킨다.
* **유지보수 및 리소스 최적화:** 트러블슈팅이 발생할 때마다 새로운 파일을 무분별하게 생성하여 파일 개수와 저장 용량을 늘리는 것을 방지한다. 지정된 소수의 도메인 파일에만 접근하여 관리 효율을 극대화한다.
* **시간 역순 누적 (Reverse-Chronological):** 각 도메인 파일 내부의 기록은 가장 최신 이슈가 맨 상단에 위치하도록 시간 역순으로 쌓아 나간다. 문서를 열람하는 즉시 현재 프로젝트 상태와 가장 연관성 높은 최신 컨텍스트를 파악하기 위함이다.
